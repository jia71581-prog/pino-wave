`data.dense_time_steps: 16 → 51`。附带 `data.dense_outer_checkpoint: false → true`,它**只为省显存**,不算第二个变量。

**同样刻意不动晚期窗的目标函数**:探针 6(2026-09-19)已测,包络目标在本装置允许的块长(K=7,17.5 ms)下

### 2.1 从头训在冻结树上起不来:必须的最小改动(已授权实现)

实测(代理 + 协调者双核对代码原文):`scripts/train_grouped_v3_ic8_fullfield_ddp.py:1212-1216`
在 `state is None`(即不传 `--fork-from`/`--resume`)时直接
`raise ValueError("LWC fork requires inherited zero anchors")`。**与卡数、显存、批次无关,从零起点根本无法启动。**

新旗标 **`--scratch-lwc-init`**,四条约束:
1. `:1214` 允许 `state is None`,**但必须断言全部 anchor 参数逐元素精确为零**再冻结。
   零断言不得省:那道 fail-closed 的实质是"anchor 必须是零",只是把"继承自父"放宽为"构造即为零"
   (它们由 `features.py:151` / `source.py:37` 的 `nn.init.zeros_` 构造,实测 abs-sum 全 0)。
2. **cs 钉 1.0 且不可训**(复用 `_CS_PIN_VALUE`:365 与 `:1222` 的冻结)。**这不是可选项**:
   `model/dense.py:82` 定义 `nn.Parameter(0.1)`,从头训实测初值 0.1、`requires_grad=True`、在优化器里,
   而钉定逻辑(`:1217-1222`)被两个强制要求 `--fork-from` 的旗标挡住 → **无 fork 不可达**。
   R2-a 整条臂证明 cs 可训会掉进门锁死的协同适应陷阱;探针实测 cs 已在下漂(12 步 0.1→0.09773)。
3. **dense output 不得零初**:零初是 fork 时为保持父函数用的,从零起没有函数要保持,零初只会让校正支路开局即死。
4. 与所有 fork 旗标及 `--resume` 互斥;必须被 `run_identity` 记录(否则 CS-2 身份门失效)。

**不动 `:1148`**(micro 护栏),本轮 `micro_batch_records` 保持 1。

## 3. 门与判读(**按单臂、无对照、欠训的性质改写**)

**前置声明**:见文首。本轮是可行性/轨迹描述性运行;**无任何真正可比的参照物**——
arm_r4 是 fork 血统且训练量完全不同,29359 训练充分,项目历史上没有过从头训的全量臂。
因此下列各项**全部作为描述性报告**,主门保留只为跨轮数值可比,不作为方法有效性的裁决。

- **主门(保留但降级为描述性)**:端点 B3(M96) 与 **0.95 × 锚(29359) = 0.5441354** 的比较。
  锚各族值从冻结 W1 面板行**重算**不硬编码(承 `judge_r4.py`)。
  **FAIL 不得被表述为"密度杠杆被证伪"**(欠训 18.7 epoch vs 锚的充分训练);PASS 则是强结论。
- **前置**:承 ADDENDUM A-2,判读前先做**锚跨树复现**(round6 树重测 29359 的 M96,要求复现
  0.5727741101838167 到 |Δ| ≤ 1e-9);不过则须改锚并声明替换。
- **~~步长匹配的单变量副对照~~**:**删除**。arm_r4 是 fork 血统、训练量不同,从零臂与它不可比。
- **非退化(描述性)**:三族 `full_mean` 与锚同族值 + 0.01 的比较,**无 floor**(承 A-1)。
- **危害发现**:任一族相对退化 > 10% 照常报(承 A-5)。
- **病态项**:`B3(U32)` / `B3(L32)` 只作完整性报告,**永不作门、永不作头条**(U32 有 11/32 条 > 1.0)。
- **NOT_DECIDABLE**:承 `load_n1` 口径(id 集合 == 冻结清单、无重复、全有限)。

**本轮真正要读的是轨迹,不是终点**:①损失是否仍在下降(未收敛 = 预算不足的直接证据,而非方法无效);
②谱核 L2 是否在向 arm_r4 的 11 量级增长及其速率;③cs 恒为 1.0(钉定生效的直接验证);
④`dense_decoder.output.weight` 的 L2 从默认初始化出发的演化。

### 3.1 必报诊断(用于区分"补上结构"与"整体拟合好一点")

1. **干预剂量的直接度量**:执行窗内**每条记录被监督到的不同帧数**(CPU,从排程枚举,零 GPU)。
   基线参照:探针 2 实测某记录 224 次访问覆盖 205/363 = 56%;51 档下该数字应显著上升。
2. **损失七项分解**:改善是否集中在晚期敏感项。arm_r4 的形态是七项**等比例**降 3-5%(无单项被改善),
   这被判为"幅度很小的全局校正"。
3. `dense_decoder.output.weight` 的 L2 轨迹。**从零臂没有父基线**:它从默认初始化出发,
   报其演化即可。参照数值(**不可作对照**):arm_r4 端点为 0.017955748364329338
   (shape (1,128,1,1) 的 Frobenius 范数,float32 累加),29359 为 0.1684。
4. 虚部/实部梯度能量比(≈0.57 表示相位自由度被真正使用;从零臂此值从随机初始化起演化)。
5. `step_seconds_max_rank` 与 `peak_gib` 逐步记录(从零臂四卡实测基线:14.013 s/步、2.5421 GiB)。

## 5. 预先声明的风险(不是事后解释)

1. **欠训是本轮头号风险(已量化)**:k05 只给 **18.7 个真实 epoch**,而 arm_r4 光把矩形谱核
   从零长到 L2≈11 就用了约 **40 个 epoch**,且那还是在其余部分都是已训权重的前提下。
   **本轮预算大约差 2 倍。** 若端点远离锚,**首要候选解释是预算不足,不是密度无效**;
   判读须先看 §3 的轨迹项(损失是否仍在下降、谱核 L2 是否仍在增长)。
2. **记录覆盖被挤压**:k05 下记录访问次数 = 4675 × 12 = **56,100**,而 arm_r4 是 224,400(**25.0%**);
   总监督帧次 = 4675 × 51 = **238,425**,arm_r4 为 299,200(**79.7%**)。
   **"记录覆盖非绑定约束"没有证据支撑**:R201 是唯一相关负结果,而
   `a4_resume_20260911/R201_CORRECTION.md` 载明它预注册 1870 步**实跑 561 步**,并明确写"不支持这一方向已失效";
   且 R201 当年**唯一改善的族恰是 marmousi(+1.32%)**,其记录自陈"抬带宽后是否复活未测"。
   判读辅助:§3.1 第 1 项(每条记录被监督到的不同帧数)能区分"帧覆盖变好但记录访问不足"与"密度本身无效"。
3. **查询点耦合**:`query_points_per_step` 不变 → 每帧查询密度降到约 1/3。探针 4 里该耦合方向**不利**于密度臂
   (它仍然赢了),但在长训里可能与风险 1、2 叠加。本轮**刻意不动**该参数以保持单变量。
4. **无对照、无可比参照**:用户明确裁决不做等预算对照;arm_r4 是 fork 血统且训练量不同,
   29359 训练充分,项目历史上没有从头训的全量臂。**因此本轮无法把任何结果归因给密度**,
   它只能回答"从零起、51 帧、18.7 epoch 能走到哪里"。
5. **cs 钉定是本轮必须承认的第二处干预**:从零起 cs 默认 `nn.Parameter(0.1)` 可训,
   钉成 1.0 不可训是新旗标带来的改变(理由见 §2.1 第 2 条:不钉则协同适应陷阱按构造是活的,实测已在下漂)。
   它不是密度变量,须在 claims 中与密度分开声明。
6. **探针证据的外推限度**:探针 4 是**一条记录、一次运行、200 步**,无族级留出证据;
   它支持"值得用一轮长训去验",**不**支持"族级一定改善"。
